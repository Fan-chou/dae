# honk 对照（2026-08-19）

> 对照对象：[daeuniverse/honk](https://github.com/daeuniverse/honk) `main`（实验版 `v0.0.1-alpha`，glassyiris）  
> 当前树：`feat/mihomo-rule-provider-groups` HEAD `4000ffc8`  
> 223：`dial_mode: domain++`，无 FakeIP，LAN 53 劫持后真实解析  
> 相关：[dns-domain-routing-2026-08-18.md](./dns-domain-routing-2026-08-18.md)、[tcp-sockmap-offload.md](./tcp-sockmap-offload.md)、[ebpf-userspace-perf-2026-08-19.md](./ebpf-userspace-perf-2026-08-19.md)

**结论：当设计对照，不要移植代码，不要当 223 的下一跳实现。**

honk 是 dae 数据面模型 + sing-box 用户态的 **Rust 实验**。配置长得像 `.dae`，内核仍是 TC + `match_set` + `dae0`/`daens`，但**不是 Go dae 的逐行移植**。维护者写明：eBPF 自己把关；DNS / 出站 / 解析器大量是 AI 写的；README 里 Reload 仍未勾选；不建议生产。

同 IP 多域名它**没有**比 kdae 做得更严：`DOMAIN_ROUTING_MAP` 仍是多 owner **OR bitmap**。kdae 已落地的 `ambiguous` + `OutboundControlPlaneRouting`（#763 收窄版）honk 没有。

---

## 1. 它是什么 / 不是什么

| | honk | kdae |
|---|---|---|
| 语言 / 加载 | Rust + aya | Go + cilium/ebpf |
| 内核模型 | dae 式 TC + match_set + `dae0`/`daens` | 同源 |
| 用户态 | sing-box 式组、多协议拨号、Clash API | olicesx 重写后的 control / DNS / mihomo 组 |
| 状态 | `v0.0.1-alpha`，破坏性变更预期 | 223 在跑 |
| 维护者勾选 | eBPF / control / 部分协议 / DNS 已审；**Reload 未审** | 已有分层 reload（`90a49840`）+ routing epoch |

不要整仓合、不要用 aya 重写、不要用 Clash API 替换 LuCI。

## 2. 值得对照（设计，不是代码）

### 2.1 DNS / 投影的 generation fence（最有用）

honk：一次查询租约钉死一整代 `DnsRuntime`（策略、hosts、upstream、投影、出站）。写 `DOMAIN_ROUTING_MAP` 前：拿 backend 锁 → 再看 generation → 过期 batch 丢掉。热重载先装好新快照再切，旧 DNS writer 写不进新 map。`dns.bind` 语义变化标 restart-required。

kdae 已有 routing epoch 双槽和 reload 时投影 DNS cache，但 fence 没有写成这么硬的一条不变量。[#1081](https://github.com/daeuniverse/dae/pull/1081) 刚把 `ChooseDialTarget` 改到 `ActiveDnsController()`，正是同一类「旧平面指针 vs 共享知识」问题。

以后若再改 DNS 投影 / 热重载：对齐「写 map 必须带 generation，切代后旧 writer 作废」，不要搬它的 `DnsService`。

文档：<https://github.com/daeuniverse/honk/blob/main/doc/en/design/dns.md>

### 2.2 路由双 bank、selector 最后翻

honk：不 `clear_routes`。编译 `RoutingPushPlan` → 填非活动 bank → 再切 `ROUTING_META_ACTIVE_GENERATION_SLOT`。一次 `route()` 只读一次 selector，看到完整旧表或完整新表。域名 bitmap 跟同一代边界走。组序号在 reload 时可能换含义，切代前把过渡槽标活（fail-open），避免旧健康位杀掉新组。

kdae 的 routing epoch slot 0/1 就是这条路。对照用，不必换 ABI。

文档：<https://github.com/daeuniverse/honk/blob/main/doc/en/design/routing.md>

### 2.3 挂载准入

`DATAPATH_STATE_MAP=0` 时 TC 原样放过；监听、map、NFQUEUE ready 之后才打开分类。关掉时先关准入再拆监听。kdae 的 datapath generation 同思路。

### 2.4 内核 `direct` 何时真卸载

honk 用 `DomainKnown`：`domain` / `domain+` / `domain++` 下，若还没有 DNS 投影、SNI 还能改 outbound，**不把非 `must` 的 `direct` 留在内核**。Clash Direct / Global 另有整表卸载规则；`must` / `block` 不被 mode 覆盖。

这比调研里「无解析 80/443 一律抬楼」更精确：不是凡 80/443 都抬，而是 **SNI 还能改判才抬**。若以后做 [dns-domain-routing §9](./dns-domain-routing-2026-08-18.md)，应对这个条件，不要无脑抬。`must_direct`（223 非白名单 MAC）仍须先于这条。

### 2.5 UDP 首包 NFQUEUE（只当参考，现在不做）

默认关，改 `experimental.udp_nfqueue.enabled` 要 **restart**。只拦 LAN 转发、内核还判不完的 UDP 首包；53 / `must` / `block` / 已可安全 direct 不进队列。token 钉在 skb mark；Direct = `NF_ACCEPT` 原 skb（真内核直连）；Proxy = 丢掉原包、一份 payload 进正常 UDP 初始化。失败 fail-closed。占用 netlink queue 320 和 nftables `inet honk_nfqueue`。

kdae 的 TC `conn_state` 已经让后续包走内核；这条只对**首包**有意义，而且和防火墙抢 nftables。[tcp-sockmap-offload.md](./tcp-sockmap-offload.md) 已拒作下一步。文档写得很清楚，代码别抄。除非明确要「UDP 首包 hold」，否则不进树。

### 2.6 路由组预过滤

按 TCP4 / TCP6 / UDP4 / UDP6 预计算规则掩码，内核一次查跳过不可能命中的链。纯性能，不动分流对错。kdae 的 `route()` 仍顺序扫 match_set；真要抠 verifier / 指令数再考虑。

## 3. 同方向、不是跟的理由

| honk | kdae |
|---|---|
| `DOMAIN_ROUTING_MAP`：IP → 规则 bitmap，多 owner **OR** | 曾经一样；`4000ffc8` 起冲突 IP 标 `ambiguous=1` 抬用户态。honk **没有**这一步 |
| 嗅探（TLS SNI / HTTP Host / QUIC Initial）只给用户态 `Router`，不写 map | 同样不写。SNI 回填约束见 dns-domain-routing §7 |
| 普通 HASH + 用户态压力淘汰（文档已从 LRU 改过来） | janitor + expire，223 有 overflow 史，不要换成 LRU |
| QUIC v1/v2 Initial 解密拼 CRYPTO | 已有 QUIC sniff。分片失败再考虑 LostAttractor `12154854`，不为对齐 honk 重写 |
| 出站计数 per-CPU map | 观测，不是分流 |

## 4. 不必跟

| 东西 | 原因 |
|---|---|
| 整仓 Rust / aya / AF_XDP | 工具链换皮，解决不了 223 的问题 |
| Clash REST / Selector 嵌套组 / SQLite persistence | 223 已有 LuCI + GraphQL/web + mihomo rule-provider |
| FakeIP | honk 自己也还在产品 TODO；kdae 明确不上 |
| eBPF 里缓存 DNS 应答 | honk TODO；map 只应存路由投影 |
| 默认打开 NFQUEUE | 见 §2.5 |
| sockmap skip-before-Update / UCI 默认开 sockmap | 与 honk 无关，223 已另有结论 |
| DnsManager / LostAttractor `next` 大重构 | 两边都不要跟 |

## 5. 对 223 / 当前树的含义

已经做完、honk 给不出更好答案的：

- [#1081](https://github.com/daeuniverse/dae/pull/1081)：`ChooseDialTarget` 用 `ActiveDnsController()`
- #763 收窄：同 IP 多域名指纹不一致 → `ambiguous` → 内核 `ControlPlaneRouting`；嗅探不写 map；不从 map 删除表达冲突

若再动手，优先顺序不变：

1. tracker 标 `ambiguous=1` 时打 debug 日志（IP、owners、两边 outbound），否则 223 无法证明抬楼打中了。
2. 可选：无解析且 **SNI 还能改判** 的 80/443（及 UDP 443）抬楼；`must_direct` 仍最先。条件对齐 honk 的 `DomainKnown`，不要「凡 80/443 无解析就抬」。
3. DNS 投影 / reload 再改时，把 generation fence 写成硬不变量。

不要 FakeIP，不要 NFQUEUE，不要移植 honk。
