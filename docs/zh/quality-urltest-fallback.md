# 节点质量、fallback / url_test 与按站点粘滞

本文档随本批改动一起交付，说明：**改了什么、怎么改、为什么、收益、代价，以及升级时要注意什么。**

一句话：节点不再只有「通 / 不通」，组策略真正对齐 Mihomo 的 `fallback` 和 `url-test`，并且同一个网站尽量粘在同一条节点上，避免看视频、打游戏时来回跳线路。

---

## 1. 给使用者看的结论

### 1.1 新增组策略

在 `group` 里可以直接写：

```dae
group {
    proxy {
        policy: url_test
        # 质量分差距小于这个值时，不换当前节点（沿用原 check_tolerance）
        check_tolerance: 50ms
    }
    backup {
        policy: fallback
    }
}
```

| 策略 | 做什么 | 和旧策略的差别 |
| --- | --- | --- |
| `fallback` | 按配置书写顺序选节点；跳过已死、以及探测/握手/业务失败造成的不可用；**相对基线变慢或拥塞不换人** | 不是 `first_alive`（`first_alive` 连失败造成的变差也不看）。也不是按延迟排序，那是 `url_test` |
| `url_test` | 在未死亡的节点里选综合质量最好的；`check_tolerance` 作用在质量分上，而不是裸延迟 | 不是 `min` / `min_avg10` / `min_moving_avg`。旧延迟策略仍可用，但不含丢包、拥塞、失能惩罚 |

`random`、`fixed`、`first_alive`、`min`、`min_avg10`、`min_moving_avg` 都保留。不想用新语义，配置不用改。

### 1.2 节点三态（Alive / Degraded / Dead）

| 状态 | 含义 | 新连接会怎样 |
| --- | --- | --- |
| Alive（健康） | 探测和实际使用都正常 | 优先选用 |
| Degraded（变差） | 还活着，但握手变慢、丢包、拥塞 | `url_test` 会用质量分避开；`fallback` **只在失败/丢包造成变差时**才换下一名；相对基线变慢仍用第一名。**不会**被写成内核 DIRECT 快路径 |
| Dead（死亡） | 连续失败，认为不可用 | 跳过，直到探测或真实回复把它救回来 |

「变差」仍算内核侧存活：已经建好的连接不会被一刀切掉，只是新连接会走用户态重新挑选。

### 1.3 按站点粘滞（只对 `fallback` / `url_test`）

嗅探到域名后，按 **eTLD+1**（`www.youtube.com` → `youtube.com`）记住这条线路；没有域名、只有目的 IP 时，按 **单播 IP**（去掉端口）钉：

- 该站后续连接优先用同一叶子节点。
- 节点死亡、这条连接失败、或连续两次对该站不友好（慢握手 / 慢首包）才会换人。
- 换人后原节点有约 60 秒冷静期，避免刚换走又立刻跳回来。
- `fallback` 另有回抢：钉住约 2 分钟后，若书写顺序更靠前的节点已经 Alive，**新连接**可以回到更高优先级（已建连接不搬家）。若这个站已经因为慢握手试过备选，则不再回抢，避免和「此站不适合第一名」对着干。
- 每个站点最多试 2 个备选；试过仍不稳就收敛，不再频繁探测。
- 环回、未指定、组播、链路本地地址，以及单标签主机名没有粘滞对象，仍走组级选择。有 SNI / FakeIP 名字时优先钉域名，不钉 FakeIP 池地址。
- 粘滞表最多约 4096 条，条目约 1 小时不用会过期。

管理界面和 Web 会显示这两种策略的**组默认当前节点**（无站点粘滞时 `Select` 的结果），并注明按站点可能不同。YouTube 和 GitHub 仍可能粘在不同叶子上。

### 1.4 规则同步（Mihomo sidecar）

| Mihomo | 现在映射到 | 以前近似成 |
| --- | --- | --- |
| `fallback` | `fallback` | `first_alive` |
| `url-test` | `url_test` | `min_avg10` |

完整生成路径把 `fallback` / `url-test` 当成无损映射，不再标 approximate（否则整次同步会被拒绝）。扁平兼容输出仍会标 approximate。未写出的 Mihomo 健康检查默认值（URL / interval / lazy）继续沿用 dae 全局探测配置。

## 2. 改了什么、怎么改的

### 2.1 节点健康（质量分）

每个节点、每种网络类型（TCP/UDP、IPv4/IPv6、DNS UDP / 数据 UDP）有独立槽位。

质量分大致是：

> 探测延迟（或移动平均） + 丢包惩罚 + 失能/拥塞惩罚 + 随时间衰减的额外惩罚

怎么观察：

- 周期性 TCP/UDP 探测：更新基线延迟、丢包窗、是否变差。
- 真实 TCP 握手时延：对比该节点自己的基线；超过约 1.5 倍视为慢（用于按站点粘滞）。**Hysteria / TUIC / Juicity 这类 UDP 出站的 TCP 槽**要到约 2 倍、或连续 3 次失败才会把整节点标成 Degraded；满速高 RTT 也不再当成拥塞。这类节点的「TCP 握手」其实是本机打开 QUIC 流（常常只有 1ms），**不写进 RTT 基线**；按站点粘滞也改用约 2 倍探测 RTT，而不是 1.5 倍那条本地握手。不足约 10ms 的样本忽略；若基线已经被钉在亚毫秒，下一次真实探测会直接重写基线。数据 UDP 槽和 TCP 出站仍用原来的严格规则。
- 首字节时间（TTFB）：只用于「这个站点是否不适合这条节点」，**不写进节点全局健康**，避免某个源站本身慢把整条节点判废。
- 数据 UDP：只有**对端回包**才证明可达；本地 `WriteTo` 成功只表示本机内核/代理收下了包。

基线用指数滑动平均，并忽略极端尖刺，避免一次偶发高延迟把「正常」标准抬上去，导致以后再也判不出变差。

### 2.2 组选择

- `fallback`：声明顺序扫描；Dead 和失败/丢包造成的不可用才跳过。相对基线变慢、拥塞仍用第一名；`url_test` 才拿质量分比延迟。
- `url_test`：在非 Dead 里比质量分；当前在用的节点享有 `check_tolerance` 滞后，避免 1ms 之差来回抖。
- 嵌套组：父组按自己的策略选子组，子组再选出叶子。`fixed` 包一层 `fallback` 时，慢握手可以排除那片叶子再试，但**不会违背用户指定的 fixed 成员**。
- 切换比较：`候选优于在用` 定义为「在用 − 候选 ≥ tolerance」；候选无效、在用有效时，候选不能赢。

### 2.3 内核 DIRECT 快路径

内核里可以把「这条出站现在就是 DIRECT」写成 BPF，新连接不用上用户态。本批收紧了条件：

- 组级选出 DIRECT，**并且**这条选择路径稳定（路径上没有 `random`）。
- `fallback` / `url_test` 里只要还有「未死的代理叶子」，就**不**写内核 DIRECT——否则拥塞的代理会被内核旁路，粘滞也无法生效。
- 竞争策略（`min` / `url_test` / `random`）要看**所有**可能赢过 DIRECT 的兄弟。
- 独占策略（`fixed` / `first_alive` / `fallback`）只看**真正选出该叶子的那条成员路径**。内置 DIRECT 是单例指针，不能靠「谁的成员列表里也有 DIRECT」反查，否则一个没用上的 fallback 兄弟会误关快路径。

### 2.4 TCP：慢握手换人，取消/空闲不记过

- 第一次握手明显慢，且组里还能选出别人时：关掉这条连接，把该站从当前节点撕开，换人再拨一次。
- `fixed` 本身不自动换成员；只有它下面还套着 `fallback` / `url_test` 时，才允许排除那片慢叶子。
- 用户取消、连接被正常关掉、空闲结束：**不**记节点故障，也**不**撕站点粘滞。

### 2.5 UDP：三种「写出成功」分开

以前容易把「放进队列」当成「对方收到了」。现在分成三层：

| 层次 | 何时 | 对健康的影响 |
| --- | --- | --- |
| 入队 | 批量 UDP 的 `Append` 返回成功 | **无**。数据还在用户态队列 |
| 本地发出 | 同步 `WriteTo` 成功，或 batch `flush` **全部**写完 | 只清「连续写失败」计数，**不**解除 Degraded，**不**冲销丢包窗 |
| 对端回复 | 收到上行回复 | 才恢复健康、衰减惩罚、冲销丢包窗 |

`flush` 部分成功（写出了一部分但又报错）不当成写成功。硬失败（如端口拒绝）计入故障；短暂软错误仍有容忍次数。

数据 UDP 没有周期性延迟探测，所以必须用真实回包来恢复；否则丢包窗会永远钉死，节点无法从「变差」出来。无变化时不反复广播质量，避免空转。

### 2.6 管理面与界面

- `fallback` / `url_test`：管理面用 Peek（不激活 lazy、不带站点粘滞）回填组级 `selected`，不再用 first_alive / 裸延迟去猜。
- `fixed` 的当前成员以运行时 `FixedIndex` 为准（持久化里的名字可能已经不在）。
- Web：显示该组默认节点，并标注「按站点可能不同」；Peek 不到时仍显示「按站点自动」。
- `fallback` / `url_test` 组成员会带上 **Alive / Degraded / Dead** 徽章和组级计数；变差原因（失败 / 变慢 / 拥塞）可在徽章提示里看到。管理 API 字段为 `admission`、`reason`。
- 节点升降级（Alive ↔ Degraded ↔ Dead）在 **debug** 日志里会写：节点、网络槽、从/到、原因、fallback 是否让位、以及 `url_test`/内核 DIRECT 的行为。

## 3. 为什么这么改

旧模型的典型问题：

1. **只有通/不通。** 节点还能拨通，但已经拥塞、丢包、握手变慢时，组策略仍当它是好节点。
2. **`fallback` / `url-test` 是假的。** 规则同步只能近似成 `first_alive` / `min_avg10`，和 Mihomo 用户预期不一致。
3. **全组共用一个「当前节点」。** 看视频的线路被一次 GitHub 探测或另一次失败拽走，站点体验抖动。
4. **内核 DIRECT 写得太勤。** 用户态刚想避开变差代理，内核还按「组里有 DIRECT」直通。
5. **UDP 把「本地发出」当成「对端可达」。** 批量发送时，包还在队列里就把失败连击清掉，死节点很难被淘汰。

本批把「探测延迟」和「实际好不好用」拆开，把「组级选人」和「这个网站该粘哪」拆开，把「本地 socket 收下」和「对端回了包」拆开。

---

## 4. 收益

- 节点变差时，新连接会避开，旧连接不必立刻掐断。
- `fallback` / `url_test` 语义可讲清楚，规则同步不再指鹿为马。
- 同一站点线路稳定，少出现播放到一半换 IP、游戏会话被拽走。
- 慢握手有一次有界重试，而不把偶发慢握手写成整节点死亡。
- 内核快路径只在「这条选择不会被粘滞改写」时开启，正确优先于省一次用户态。
- UDP 故障判定更老实，批量发送不再掩盖真实失败。

## 5. 代价与副作用（请先读）

1. **组默认节点不是每个站的粘滞叶子。** 面板上的当前节点是无站点时的组级选择；具体域名可能粘在别的叶子上。
2. **已有 `first_alive` / `min_*` 配置不会自动获得新语义。** 要用三态和粘滞，必须改成 `fallback` 或 `url_test`。
3. **粘滞会让「组里延迟最低的节点」不一定接到每一个站。** 这是故意的：稳比每毫秒最优更重要。若希望永远抢最低延迟，继续用 `min` / `min_moving_avg`。
4. **变差节点不写内核 DIRECT，用户态选路会多一些。** CPU 和延迟可能略增，换来「拥塞代理不会被内核旁路」。
5. **慢握手重试会拆掉第一次连接。** 首包路径可能多一次 RTT；只在组里确实还有别人可试时发生，且最多一次。
6. **冷静期约 60 秒；fallback 约 2 分钟后允许回抢更高优先级。** 刚换走时不会立刻跳回。若更高优先级只是当时不可用、后来恢复了，新连接大约 2 分钟后有机会回去；已经因该站慢而试过备选的，不会每两分钟再抢一次。已建连接始终不搬家。
7. **UDP 更保守。** 只发出去、没有回包时，节点会在 Degraded 上待更久。单向 UDP（某些游戏心跳只有上行）可能更晚被判好；这比把队列成功当成可达更安全。
8. **质量分不是「纯 ping」。** 丢包、拥塞惩罚可能让 ping 稍高但更稳的节点赢。看裸延迟的人会觉得「怎么没选最快的」。
9. **粘滞表占用内存。** 上限约 4096 站点；极端多域名环境会淘汰旧条目，新站回到组级选择。
10. **规则同步的扁平输出仍可能标 approximate。** 完整生成路径不再因此拒绝 `fallback` / `url-test`。未写出的 Mihomo check URL / interval / lazy 仍用 dae 全局探测配置。
11. **TTFB 不用来打节点全局分数。** 某个源站本身慢，不会连累该节点上的其他站；代价是「节点整体变慢」更多依赖握手和探测，而不是页面首字节。
12. **UDP 出站（Hysteria / TUIC / Juicity）的 TCP 槽更宽松。** 偶发慢探测或单次失败不再把整节点标成 Degraded，满速高 RTT 也不再当拥塞。本地 QUIC 流打开不进基线，按站点粘滞用约 2 倍探测 RTT 判断「这个站慢」，避免几乎每个 HTTPS 都被当成站点慢而粘到下一名。真死了（Alive=false）`fallback` 仍会跳过。TCP 出站和数据 UDP 写出语义不变。
13. **`fallback` 不比延迟。** 第一名只是比自己平时慢、或看起来拥塞时，不会换成后面的节点；探测/握手/业务失败造成的不可用才会让位。要比综合质量用 `url_test`。

## 6. 升级对照

| 你原来怎么用 | 升级后建议 |
| --- | --- |
| 配置未写 `fallback` / `url_test` | 行为保持旧策略；本批健康槽仍会记录，但旧策略选人逻辑基本不变 |
| Mihomo `fallback` 被同步成 `first_alive` | 会变成真正的 `fallback`：可能开始跳过「变差但未死」的节点 |
| Mihomo `url-test` 被同步成 `min_avg10` | 会变成 `url_test`：可能不再选 ping 最低、而是质量分最低的节点 |
| 面板依赖「组当前节点」 | `fallback` / `url_test` 显示组默认叶子，并注明按站点可能不同 |
| 用 UDP 本地发送成功来判断节点活着 | 不再成立；请以回包或探测为准 |

回滚：把组策略改回 `first_alive` / `min_avg10` / `min_moving_avg` 即可回到旧选人语义。健康三态和 UDP 写出分层仍在数据面；若必须完全回到「写出即成功」，需要另一次代码回退，而不是只改配置。
